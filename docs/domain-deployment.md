# Đưa Portfolio FPT Hub lên tên miền riêng

Kiến trúc hiện tại: GitHub Pages chạy React/Vite; API Express chạy riêng (repo có `render.yaml` cho Render); MongoDB lưu tài khoản, đơn hàng và chứng từ; Resend gửi OTP xác thực đăng ký. Việc mua tên miền hoặc trỏ DNS **không** tự triển khai API.

Bạn có thể triển khai API trước khi mua tên miền: tạm đặt `CLIENT_ORIGIN=https://thietbvhe186481.github.io` và `VITE_API_URL` là URL HTTPS của API. Sau khi có tên miền, đổi hai biến này sang địa chỉ mới rồi triển khai lại. Trong giai đoạn dùng hai domain khác nhau, giữ `COOKIE_CROSS_SITE=1` theo `render.yaml`.

Ví dụ bên dưới dùng `www.example.vn` cho web và `api.example.vn` cho API. Thay bằng tên miền thực tế sau khi đăng ký; chọn `www` hoặc tên miền gốc làm địa chỉ chính rồi dùng nhất quán.

1. **Triển khai API và MongoDB trước.** Tạo MongoDB Atlas hoặc MongoDB trên máy chủ của bạn. Tạo database user và cho phép IP máy chủ API trong Atlas Network Access. Trên database mới, chạy `npm run bootstrap:production` một lần với `MONGODB_URI`, `BOOTSTRAP_ADMIN_EMAIL` và `BOOTSTRAP_ADMIN_PASSWORD` (ít nhất 14 ký tự) trong môi trường chạy lệnh; có thể chạy lại khi cần bổ sung bài tập/học liệu mới. Lệnh tạo admin, gói Premium và danh mục công khai còn thiếu; không thêm tài khoản demo và không xóa/ghi đè dữ liệu đã có. Sau khi chạy, bỏ biến mật khẩu bootstrap khỏi môi trường. Với Render, tạo Web Service/Blueprint từ repo bằng `render.yaml`, nhập `MONGODB_URI`, `CLIENT_ORIGIN=https://www.example.vn`, `SESSION_SECRET`, `OTP_SECRET`, `RESEND_API_KEY`, `EMAIL_FROM`. Không nhập các khóa bí mật vào GitHub Pages hoặc biến `VITE_*`. Kiểm tra `https://<api-host>/api/health` trả về `ok: true`.
2. **Gắn tên miền API.** Trong Render > Service > Settings > Custom Domains, thêm `api.example.vn`; lấy đúng bản ghi DNS Render hiển thị (thường là CNAME tới hostname `onrender.com` của service), thêm tại nhà cung cấp tên miền rồi Verify. Bật HTTPS. Nếu dùng VPS, cấu hình HTTPS reverse proxy cho API thay cho bước Render.
3. **Gắn tên miền web.** Trong repo GitHub > Settings > Pages > Custom domain, nhập `www.example.vn`. Trong DNS, tạo CNAME `www` tới `thietbvhe186481.github.io`. Nếu muốn tên miền gốc `example.vn` cũng hoạt động, cấu hình bản ghi A/ALIAS theo hướng dẫn GitHub Pages và chuyển hướng về địa chỉ chính. Với GitHub Actions Pages như repo này, không cần tạo file `CNAME` trong mã nguồn. Bật **Enforce HTTPS** sau khi chứng chỉ sẵn sàng.
4. **Build đúng đường dẫn và nối API.** Trong GitHub repo > Settings > Secrets and variables > Actions > Variables, đặt `VITE_BASE_PATH=/` và `VITE_API_URL=https://api.example.vn` (không có `/api` ở cuối). Đẩy một commit hoặc chạy lại workflow `Deploy Portfolio to GitHub Pages`. Khi còn dùng URL mặc định `https://thietbvhe186481.github.io/EXE301/`, giữ `VITE_BASE_PATH=/EXE301/` hoặc không đặt biến này.
5. **Bật email đăng ký.** Xác thực tên miền gửi mail với Resend bằng các bản ghi DNS họ cung cấp; đặt `EMAIL_FROM=Portfolio FPT Hub <no-reply@example.vn>` và `EMAIL_VERIFICATION_REQUIRED=1` trên API. OTP email dùng để xác minh tài khoản; thanh toán không cần OTP. Đặt `PAYMENT_PROVIDER=manual` để dùng TPBank/VietQR và admin đối soát, hoặc cấu hình đầy đủ PayOS nếu dùng cổng thanh toán.
6. **Kiểm thử trước khi nhận tiền thật.** Kiểm tra đăng ký/OTP và đăng nhập của từng role, mentor được duyệt mới nhận bài, sinh viên tạo đơn đúng gói, QR hiển thị đúng người nhận, admin đối soát mới kích hoạt Premium và ghi log chi trả mentor. Xem [quy trình thanh toán](payment-operations.md). **Không chạy `npm run seed` trên database đang có dữ liệu**, vì lệnh này xóa nhiều collection trước khi nạp dữ liệu demo.

Khi bạn có tên miền thật và nhà cung cấp DNS, cần thay `example.vn` bằng tên thật, kiểm tra bản ghi DNS/HTTPS, rồi chạy kiểm thử trên môi trường thật. Không gửi mật khẩu, chuỗi kết nối MongoDB hay API key qua tin nhắn; nhập chúng trực tiếp vào phần Environment/Secrets của dịch vụ triển khai.
